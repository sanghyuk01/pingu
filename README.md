# Pingu 🐧

펭귄 핑구가 연결의 안부를 묻는, 데이터베이스 없는 ICMP·HTTP 모니터링 도구입니다.

Go 서버 하나가 화면, API, 검사 스케줄러를 모두 제공합니다. HTML·CSS·JavaScript·SVG는 `go:embed`로 실행 파일에 포함되며, 프런트 빌드나 Node.js 런타임이 필요하지 않습니다. 현재 구현은 로컬 개발용으로 검증했으며 외부에 배포하지 않았습니다.

## 로컬 실행

Go 1.26 이상이 설치되어 있어야 합니다.

```sh
go run .
```

브라우저에서 <http://127.0.0.1:8080>에 접속합니다. `make build`로 빌드하면 `./bin/pingu`만으로 실행할 수 있습니다. 화면을 수정한 경우 다시 빌드하거나 `go run .`을 재시작합니다.

## 사용 방법

1. **새 작업 만들기**를 누르고 이름과 대상을 입력합니다. 주소는 한 줄에 하나씩 입력합니다.
2. IP·호스트 이름은 ICMP로, `http://`·`https://` URL은 HTTP로 확인합니다.
3. 검사 간격, 전체 실행 시간, 개별 검사 제한시간을 설정하고 **핑 보내기 시작**을 누릅니다.
4. 대시보드에서 응답시간, 성공률, 최근 결과를 확인합니다. 작업 이름을 누르면 대상별 최근 60건을 볼 수 있습니다.
5. 진행 중인 작업을 중지하고, 끝난 작업은 삭제할 수 있습니다.

검사는 브라우저가 아닌 Go 서버에서 실행됩니다. 화면을 닫아도 계속됩니다. 같은 대상의 이전 검사가 진행 중이거나 동시 실행 한도에 도달하면 검사를 생략하고 별도로 집계합니다. 밀린 요청을 무한히 쌓지 않습니다. 종료·중지로 취소된 검사는 네트워크 실패로 집계하지 않습니다.

첫 검사는 대상들을 한 간격 안에 분산하여 시작합니다. 작업 시간이 간격보다 짧다면 실행 시간 안에 분산합니다. 초당 20회 한도가 우선하므로 아주 짧은 작업에 대상이 많으면 모든 대상의 검사를 완료하지 못할 수 있습니다. 작업 종료 시 진행 중인 요청도 취소합니다.

HTTP는 `HEAD` 요청을 사용하며, 405·501 응답에 한해 제한된 `GET` 요청으로 다시 확인합니다. 200~299만 성공으로 처리하고 리다이렉트는 따르지 않습니다. 검사량 한도는 예약 검사 기준이며 이 GET 대체 요청·DNS·TLS 패킷 수까지 의미하지는 않습니다. 응답시간은 DNS·연결 수립·필요시 TLS·대체 요청을 포함한 전체 검사 경과 시간이고, 평균·최소·최대는 성공한 검사 기준입니다. HTTP 본문은 저장하지 않습니다. ICMP 무응답만으로 서버 장애를 확정할 수는 없습니다.

## 보관과 한도

| 항목 | 동작 |
| --- | --- |
| 작업 정의 | `data/jobs.json`에 원자적으로 저장 |
| 검사 결과·통계 | 메모리에만 저장, 재시작하면 초기화 |
| 대상별 이력 | 최근 60건 |
| 전체 최근 소식 | 최근 60건 |
| 서버 재시작 | 진행 중인 작업을 `중단` 처리, 자동 재개하지 않음 |
| 종료 작업 | 24시간 후 자동 삭제 |
| 전체 작업 | 최대 100개 |
| 전체 대상 | 보관 중인 모든 작업을 합쳐 최대 1,000개 |
| 예약 검사 시작 | 전체 초당 최대 20회 |
| 동시 검사 | 최대 64개 |
| 검사 간격 | 1초~24시간 |
| 실행 시간 | 1초~24시간 |
| 개별 제한시간 | 1~10초 |

작업 생성·중지·삭제·완료·자동 정리 시에만 설정 파일을 씁니다. 목록 API에는 대상별 최신 결과와 요약만 보내고, 전체 최근 이력은 상세 화면을 열 때 조회합니다. 숨겨진 브라우저 탭은 자동 조회를 멈춥니다. 실제 메모리·CPU 사용량의 운영 부하 벤치마크는 아직 진행하지 않았습니다.

JSON 파일과 메모리를 사용하는 **단일 프로세스 전용** 구조입니다. 여러 인스턴스가 동일한 파일을 공유하는 구성은 지원하지 않습니다.

## 환경변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PINGU_ADDR` | `127.0.0.1:8080` | 바인딩 주소 |
| `PINGU_DATA` | `data/jobs.json` | 작업 정의 파일 |
| `PINGU_TOKEN` | 없음 | API 접속 토큰. 외부 바인딩에는 24자 이상 필수 |
| `PINGU_ALLOW_PRIVATE` | `false` | `true`일 때 사설망·루프백 대상 검사 허용 |

토큰이 설정된 서버는 화면의 **서버 연결**에서 토큰을 입력합니다. 토큰은 브라우저의 세션 저장소에만 보관합니다. 공인 주소만 허용하는 기본 모드에서는 실제 연결 직전 DNS 결과의 IP도 검증합니다. 환경변수로 내부망 검사를 허용한 경우 해당 서버에 API 접근 권한이 있는 운영자만 사용해야 합니다. 외부 공개 시 HTTPS를 적용합니다.

ICMP는 IPv4·IPv6 공유 소켓을 각각 사용합니다. 비특권 ping socket을 우선 사용하고, 실패하면 raw socket을 시도합니다. 둘 다 열 수 없는 환경에서는 HTTP 검사는 가능하며 ICMP 검사 결과에 권한 오류를 표시합니다. Linux 비특권 소켓은 실행 그룹에 대한 `net.ipv4.ping_group_range` 설정이 필요할 수 있습니다. 아래 Compose 설정에는 해당 그룹 설정이 포함되어 있습니다.

## Docker로 로컬 실행

```sh
cp .env.example .env
# .env의 PINGU_TOKEN에 24자 이상의 임의 값을 입력합니다.
# 예: openssl rand -hex 24
docker compose up --build
```

이 명령은 로컬 컨테이너 하나를 실행합니다. DB·Redis·별도 프런트 서버는 없습니다. 기본 포트는 호스트 루프백에만 노출합니다. 설정 파일은 `pingu-data` 볼륨에 보관하며 결과는 컨테이너 재시작 시 초기화합니다. 컨테이너의 128MB 제한은 실행 제한값이고 해당 크기에서의 최대 처리량을 보장하는 벤치마크 결과는 아닙니다.

## API

토큰을 설정했다면 `Authorization: Bearer <token>` 헤더가 필요합니다.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/healthz` | 프로세스 상태 |
| GET | `/api/status` | 버전·ICMP 사용 가능 여부 |
| POST | `/api/jobs` | 작업 생성 및 즉시 시작 |
| GET | `/api/jobs` | 작업 요약·최신 결과·전체 최근 소식 |
| GET | `/api/jobs/{id}` | 대상별 전체 최근 이력 |
| POST | `/api/jobs/{id}/stop` | 중지 |
| DELETE | `/api/jobs/{id}` | 삭제, 실행 중이면 검사도 취소 |

```json
{
  "name": "서비스 점검",
  "addresses": ["https://example.com", "1.1.1.1"],
  "interval": 10,
  "duration": 1800,
  "timeout": 2
}
```

시간 값은 모두 초 단위입니다.

## 검증

```sh
go test -race ./...
go vet ./...
node --check web/app.js
```

테스트는 고정 크기 이력, 전체 속도·동시성 한도, 작업 종료 시 취소, 재시작 복구, 사설 주소 차단, HTTP 대체 요청·리다이렉트 제한, ICMP 루프백, 토큰·Origin 검사, 작업 생명주기를 다룹니다. ICMP 소켓을 열 수 없는 테스트 환경에서는 루프백 테스트를 건너뜁니다.

## 프로젝트 구조

```text
main.go                    # 화면 내장, HTTP 서버, 종료 처리
internal/monitor/          # 메모리 작업 관리, 스케줄러, ICMP·HTTP 검사
internal/server/           # API, 토큰, 정적 파일 제공
web/                       # 반응형 대시보드, 직접 그린 펭귄 SVG
Dockerfile                 # 단일 실행 파일 컨테이너
compose.yaml               # 로컬 컨테이너 실행 설정
```
